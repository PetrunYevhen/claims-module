# Вимоги до програмного продукту «Claims Module»

Система керування страховими виплатними справами (claims): прийом повідомлення про страховий випадок (FNOL — First Notice of Loss) та керування фінансовими резервами. Вимоги сформульовано за реалізованою поведінкою системи для навчального проєкту.

## 1. Проблема та мета

Страхова компанія отримує повідомлення про збитки (ДТП, пожежа, крадіжка тощо). Без єдиної системи дані розпорошені, статус справи неясний, а рішення про виплатні резерви ухвалюються без контролю повноважень. Продукт вирішує це так:

- фіксує випадок і всіх учасників в одному записі;
- веде справу за чітким життєвим циклом;
- розподіляє право затверджувати резерви залежно від суми;
- зберігає незмінний журнал усіх дій.

## 2. Користувачі (ролі)

| Роль | Код | Можливості |
|---|---|---|
| Спеціаліст із претензій | `handler` | Створює справи, додає сторони й документи, відкриває резерви до $10 000 |
| Супервайзер | `supervisor` | Усе, що handler, + затверджує резерви до $100 000, керує статусами, перевідкриває справи |
| Менеджер | `manager` | Усе, що supervisor, + затверджує резерви до $10 000 000, знімає агрегатний ліміт |

## 3. Функціональні вимоги (FR)

| ID | Вимога |
|---|---|
| FR-1 | **Реєстрація справи (FNOL).** Три кроки: поліс і подія; сторони й об'єкти ризику; початковий резерв. Номер справи генерується автоматично у форматі `CLM-YYYY-NNNNNNN`. |
| FR-2 | **Життєвий цикл.** Статуси: Draft, Open, UnderInvestigation, PendingPayment, Closed, Reopened, Withdrawn. Недопустимий перехід відхиляється. |
| FR-3 | **Сторони й об'єкти ризику.** Сторони (заявник, застрахований, свідок, третя особа, адвокат) та об'єкти ризику (транспорт, майно, особа, обладнання, інше). |
| FR-4 | **Резерви.** Резерви за компонентами (indemnity, expense, ALAE, subrogation) з історією змін; рівень затвердження залежить від суми. |
| FR-5 | **Документи.** Завантаження й перегляд документів до справи. |
| FR-6 | **Список і пошук.** Список справ із пагінацією, фільтрами й пошуком; сторінка справи з вкладками (огляд, сторони, резерви, документи, аудит). |
| FR-7 | **Журнал аудиту.** Журнал, який лише доповнюється. |
| FR-8 | **Фонова перевірка.** Справи, які не оновлювались понад 48 годин, позначаються в журналі. |

## 4. Нефункціональні вимоги (NFR)

| ID | Вимога |
|---|---|
| NFR-1 | **Безпека.** Автентифікація через JWT, перевірка ролей на бекенді та в інтерфейсі. |
| NFR-2 | **Цілісність даних.** Створення справи з дочірніми записами в одній транзакції; номери справ не повторюються. |
| NFR-3 | **Обробка помилок.** Помилки валідації повертаються як 422 з описом поля. |
| NFR-4 | **Розгортання.** Docker Compose; автотести в CI. |

## 5. Ключові бізнес-правила

- **BR-1.** Ліміти затвердження резерву: ≤ $10 000 — автоматично; ≤ $100 000 — supervisor; ≤ $10 000 000 — manager.
- **BR-2.** Користувач не може затвердити резерв, який створив сам.
- **BR-3.** Резерв потребує прив'язаного полісу.
- **BR-4.** Справу не можна закрити, поки є резерви на погодженні.
- **BR-5.** Перевідкрити закриту справу може лише supervisor із зазначенням причини.
- **BR-6.** Вимоги до введених даних: дата збитку не в майбутньому, коректний код причини збитку, наявність заявника.

## 6. Поза обсягом

Виплати, суброгація, судові спори, оцінка шахрайства, перестрахування, масові операції, листування з клієнтами.
